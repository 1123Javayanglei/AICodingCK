# 测试

这个项目没有 npm / 构建工具 / 测试框架, 双击 `index.html` 就跑。所以测试也只能
用浏览器当运行器: 每个用例是一个 HTML 页面, 加载真实的 `app.js` / `questions.js`,
用脚本模拟点击, 把 `PASS` / `FAIL` 写进页面里的 `<pre>` 块, 再用无头浏览器
`--dump-dom` 把结果抓出来。

## 跑

```
bash tests/run.sh            # 全部
bash tests/run.sh qb_essay   # 只跑一个
```

或者双击 `tests/run.bat`(只是转发给 `run.sh`)。

全绿时退出码 0, 有失败退出码 1。共 776 条断言。

## 三个坑

**分节名会在题型之间重名。** 单选题和阅读理解都有"练习一", 拿
`sections.forEach(s => SEC[s.name] = s.id)` 建映射时后一个会盖掉前一个, 于是
`curQ()` 全查不着, 用例从第二条断言开始抛异常 —— 而 `run.sh` 只数 `PASS`/`FAIL`
行, 抛异常等于"没有 FAIL", 看起来是全绿。建映射时键要带上题型
(`题型名/分节名`), 别只认分节名。smoke8 就是这么哑掉的。

**每个用例必须用独立的 `--user-data-dir`。** 共用 profile 时上一个用例写进
localStorage 的偏好(比如「选项乱序」)会被下一个用例读到, 冒出一堆假失败。
`run.sh` 里已经按用例名分目录了, 跑完用 EXIT trap 收掉(正常退出 / exit 1 /
Ctrl-C 都会触发)。注意别往 trap 里加 `INT` —— 那样 Ctrl-C 只会执行清理然后
继续跑循环。

**结果块的 `<pre>` 开标签和第一条结果是同一行。** 抓取时得先把标签换掉再按
`<` 切行, 否则第一条 `PASS` 会被吃掉; 如果第一条正好是 `FAIL`, 会被整个漏掉。
`run.sh` 里处理了。

## 加用例

照抄任意一个 HTML 的结构: 引入 `../questions.js` / `../explanations.js` /
`../essay-rubrics.js` / `../dict.js` / `../app.js`, 用 `ok(条件, '用例名', 实际值)`
记断言, 最后建一个 `id="out"` 的 `<pre>` 装结果。然后加进 `run.sh` 的
`HTML_TESTS`(`run.bat` 只是转发, 不用改)。

用例要 `await` 的话(比如等悬停的 120ms 延迟), 把整个 IIFE 写成 `async`, 结果块
放在最后 —— `run.sh` 是在 `--virtual-time-budget` 跑完之后才抓 DOM 的, 异步照样收到。
